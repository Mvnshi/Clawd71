# Generator hypothesis ledger (Phase 2)

Format per hypothesis: statement, historical evidence, implementation,
parameters searched, prediction, test result, verdict. A hypothesis is
**retained** only if it beats an appropriate random null model on
out-of-sample (walk-forward) prediction of withheld solved puzzles --
fitting the training data is not sufficient (see Phase 3/4 anti-bullshit
rule).

Populated by the Phase 2-4 research workflow. Six hypotheses were
formalized, implemented, and tested against the 70 verified solved
puzzles in `data/solved_puzzles.json`. **All six were rejected or found
unfalsifiable with zero recoverable predictive structure.** None
survives walk-forward validation (see `research/walk_forward_validation.md`).
Full code and result JSON/MD for each hypothesis live in
`research/hypotheses/`.

---

## 1. Sequential / arithmetic counter (`seq_counter`)

**Hypothesis.** The "deterministic wallet" underlying Bitcoin Puzzle keys
is a literal sequential integer counter: there exists a base
offset/step such that `raw_key(n) = base + step*n` (or a simple
polynomial in `n`), and the puzzle setter's "masking to set difficulty"
simply truncates `raw_key(n)` to its low `(n-1)` bits and forces bit
`(n-1)` high. If true, consecutive puzzles' low bits should differ by
the same small constant step almost every time.

**Historical evidence.** The creator's own quoted statement ("just
consecutive keys from a deterministic wallet, masked with leading
000...0001 to set difficulty") is exactly the plain-language version of
this hypothesis, which is what motivated testing it first. No
independent primary-source corroboration of the specific arithmetic
form was found in Archaeology beyond the quote itself (see
`research/archaeology/creator_statements.md`).

**Implementation.** `research/hypotheses/seq_counter.py` (stdlib only,
manual Spearman fallback since scipy was unavailable at time of run).
Computes `delta(n) = (L(n+1) mod 2^(n-1)) - L(n)` for `n=1..69`,
`diff2(n) = key_int(n+1) - 2*key_int(n)`, Spearman rank correlation of
`n` vs normalized position, ascending/descending run fraction, and
chi-square uniformity of the last hex digit of `key_int`. Compared
against a 20,000-trial Monte Carlo null of synthetic 70-puzzle datasets
with each key drawn independently uniformly from `[2^(n-1), 2^n)`.
Walk-forward: fit modal delta-step on puzzles `n=10..N-1`, predict
puzzle `N+1`'s normalized position, for `N` in {20,30,40,50,60}.

**Parameters searched.** Every integer value that actually occurred as
a delta across the 60 testable consecutive pairs (`n=10..69`) was
checked for repetition (a comprehensive search over all candidate
constant steps, since a real step fitting `k` pairs would show up as a
Counter value with count `k`).

**Prediction.** If true, nearly all 60 consecutive-puzzle pairs
(`n>=10`, where the modulus `2^(n-1)` is astronomically larger than any
plausible small step, ruling out wraparound) should share one constant
delta value.

**Test result.** Max repeated-delta frequency among the 60 pairs: **1/60**
— literally no constant step recurs even twice. Unique-delta count
68/69. |Spearman rho| = 0.1814. Chi-square on last hex digit = 17.000.
Monte Carlo p-values: 1.000 (max-repeat), 0.880 (unique-delta count),
0.209 (|Spearman|), 0.322 (chi-square) — all statistically
indistinguishable from the null built from 20,000 independent-uniform
synthetic datasets. Walk-forward: modal-step predictor beat the naive
midpoint baseline in only 2 of 5 splits (a coin flip).

**Reason rejected.** The hypothesis makes a sharp, falsifiable
prediction (near-universal shared step) that is completely absent from
the data: not even two of 60 pairs share a delta. Every statistic tested
falls squarely inside the random-null distribution (p = 0.21-1.00), and
the walk-forward fit shows no systematic edge. This is a clean, decisive
rejection: the data actively contradicts the "raw arithmetic sequence
truncated to set difficulty" literal reading of the creator's statement,
while remaining fully consistent with the creator's plainer "no pattern"
claim (i.e., consistent with keys being independent uniform draws within
each forced interval). **Verdict: rejected.**

## 2. Linear congruential generator (`lcg`)

**Hypothesis.** Puzzle keys (before masking) were generated by an LCG
`x_{i+1} = (a*x_i + c) mod m`, with puzzle `n`'s key related to LCG
output `n` via the stated masking transform (force high bit `n-1`, keep
low `n-1` bits).

**Historical evidence.** Not directly tied to a specific primary source;
tested because LCGs are a common "amateur deterministic generator"
choice and because the creator's "deterministic wallet" phrase is vague
enough to admit this reading. The creator's own account (sequential
keys from a deterministic wallet) points more toward BIP32/BIP44-style
HD derivation than a raw LCG, which is broadly consistent with (though
not proof against) the negative result below.

**Implementation.** `research/hypotheses/lcg.py` (numpy + pure-Python
bigints, seed 20260819, ~3s runtime). Four independent tests, each with
its own matched Monte Carlo null: (A) direct search over power-of-two
moduli `2^4..2^24`, solving `(a,c)` from consecutive triples and scoring
match fraction across all 69 transitions; (B) determinant/GCD
modulus-recovery (Plumstead/Boyar) in exact arbitrary-precision
arithmetic on a common `2^69` scale; (C) lattice/spectral structure via
184 small coprime `(p,q)` directional chi-square projections plus
nearest-neighbour clustering; (D) walk-forward 3-consecutive-output
state-recovery attack across 5 candidate moduli, MSE vs naive midpoint
baseline.

**Parameters searched.** Test A: 21 power-of-two moduli. Test B: exact
common-scale integers, gcd of 67 determinant values, plus an `n>=20`
robustness subset. Test C: 184 directions, 20-bin chi-square each. Test
D: moduli `2^8, 2^12, 2^16, 2^20, 2^24`, walk-forward over `n=4..69`.

**Prediction.** A real LCG would produce a recoverable modulus via GCD,
an unusually high match-fraction at some small modulus, lattice/spectral
clustering beyond chance, and a 3-output state-recovery predictor that
beats the midpoint baseline out of sample.

**Test result.** Zero of four tests exceeded their matched null. Test A
best-modulus match fraction 0.1449 (null mean 0.1484). Test B gcd=4
(`log2`=2.00, null mean `log2`=3.01). Test C max chi-square 41.43 (null
mean 40.70); nearest-neighbour distance 0.0171, *larger* (less
clustered) than the null mean 0.0105. Test D: walk-forward MSE beat the
midpoint baseline at only 1 of 5 moduli, 0/132 exact hits.

**Monte Carlo p-values.** A=0.7176, B(corrected)=1.0000 (also 1.0000 on
the `n>=20` robustness subset), C(chi-square)=0.3905,
C(nearest-neighbour)=0.8824. All far from significance.

**Reason rejected.** All four tests return statistics indistinguishable
from — in one case literally weaker than — a matched random-control
null. A notable methodological event during Test B: an initial null
construction produced an apparently significant result (p=0.0005) purely
from an uncontrolled confound (small-`n` positions have mechanically
forced trailing-zero bits from the varying `2^(n-1)` denominator,
unrelated to any generator); once corrected to match that structural
feature, the result flipped to fully non-significant (p=1.0000),
independently confirmed on the `n>=20` subset immune to the confound.
This episode is exactly the kind of spurious pattern the anti-bullshit
rule is meant to catch, and catching it reinforces confidence in the
other three tests, which were negative from the start. **Verdict:
rejected.**

## 3. Non-cryptographic PRNG: xorshift / Mersenne Twister (`xorshift_mt`)

**Hypothesis.** Puzzle #71-family private keys were generated by a
non-cryptographic PRNG with known internal structure — xorshift32/64/128,
or MT19937 (Python's `random` module / C `rand()` / general Mersenne
Twister) — used directly (masked raw output) or seeded with something
guessable (small integer 0..100,000, or a Unix timestamp during 2015,
the puzzle series' creation year).

**Historical evidence.** Funding tx confirmed on-chain 2015-01-15
18:07:14 UTC (block 339085). The creator's 2017 BitcoinTalk statement
points toward a BIP32/BIP44-style HD wallet, not a raw non-crypto PRNG.
An independent prior community study
(`mlartab/bitcoin-puzzle-systematic-analysis`, documented in
`research/archaeology/creator_statements.md` §4b) already ran a full
32-bit seed-space exhaustive search against Python `random`/C
`rand()`/Java `Random` plus a Z3 SAT-solver MT19937-state-recovery
attempt targeting puzzle #71 specifically, and reported a negative
result ("wasn't made with Python's random... likely doesn't use MT19937
at all"). This work is an independent from-scratch replication/extension
of that finding, not a reliance on it.

**Implementation.** `research/hypotheses/xorshift_mt.py`. Two
falsification strategies: (A) GF(2) linear-recurrence test brute-forcing
all 59,582 candidate xorshift shift-xor transforms against every real
consecutive-puzzle pair's low-32-bit words (37 pairs) and low-64-bit
words (5 pairs); (B) PRNG-replay brute force building a full 70-output
stream per seed and recording the longest run of exact-match consecutive
puzzles, both overall and restricted to `n>=10`. `multiprocessing.Pool(4)`
parallelized replay searches; every result compared against a Monte
Carlo null of the same search re-run on independently redrawn random
control data.

**Parameters searched.** Part A: 59,582 (pattern, a, b, c) linear maps ×
{32-bit, 64-bit} word widths. Part B: xorshift32/64/128 seeds
1..2,000,000 each; MT19937 small-int seeds 0..100,000; MT19937
Unix-timestamp seeds spanning all of 2015 at 1-second granularity
(31,536,000 seeds). Total ~37.6 million distinct PRNG-replay hypotheses.

**Prediction.** A real xorshift stream would have one shift-triple
correctly mapping every consecutive pair; a real seed would reproduce
3+ consecutive puzzles' lower bits exactly, at a rate far exceeding a
matched random-control search.

**Test result.** Part A: best triple scored 0/37 hits (w=32) and 0/5
hits (w=64) — not even one pair matched. Part B: longest exact-match run
found anywhere tops out at 6-7, and every such maximum starts at puzzle
`n=1` (trivial, 0 free bits, always "matches"). Restricted to `n>=10`,
the longest run for any generator is only 2 consecutive puzzles. No seed
anywhere reproduced 3+ consecutive puzzles outside the trivial region.

**Monte Carlo p-values.** Part A: p=1.000 for both word widths. Part B
(`n>=10`, the decisive metric): p=1.000 for all five generator/seed
combinations. Part B (overall, trivial small-n metric, for
completeness): p=0.500-1.000, with the MT19937-timestamp-2015 sweep's
null actually *exceeding* the real result outright in one replicate (a
control run produced length-8 vs the real 7).

**Reason rejected.** Both tests are completely negative and
indistinguishable from — in one case literally beaten by — a matched
random-null Monte Carlo control at identical search scale. Per the
anti-bullshit rule this is a plain, valid negative result. It is
consistent with the creator's own stated "deterministic wallet"
(HD/BIP32-style, not raw non-crypto PRNG) origin and with the prior
independent community study targeting #71 directly. **Verdict:
rejected.**

## 4. Hash / HMAC / BIP32 chain (`hash_chain`)

**Hypothesis.** Puzzle keys are produced by a cryptographic hash/HMAC
construction over the index `n` (and/or previous key): (a) salted hash
`k_n = SHA256(seed||n) mod range_n`, (b) hash chain
`k_n = SHA256(k_{n-1}) mod range_n`, or (c) BIP32 non-hardened
derivation `child_priv = (parent_priv + HMAC-SHA512(chaincode,
parent_pub||n)[:32]) mod secp256k1_order`.

**Historical evidence.** Not applicable as external corroboration — this
hypothesis class is not falsifiable via seed recovery from 70 outputs
under standard cryptographic assumptions (that would break
SHA-256/HMAC-SHA512 as a PRF). The only testable prediction is
statistical randomness of output bits. Archaeology surfaced two
concretely testable *specific instances* of this family worth a
follow-up dictionary-attack pass rather than pure statistics: Electrum's
Type-1 `old_mnemonic.py` additive scheme (`child_privkey = (secexp + z)
mod curve_order`, confirmed from source) and the classic Type-1
deterministic-wallet formula `SHA256(masterstring + str(n))` (Mike
Caldwell, 2011, well documented on the Bitcoin wiki). Both require a
guessable seed/passphrase to be practically testable and were flagged in
Archaeology as unfinished business, not run to completion in this phase.
The dataset's observed randomness (below) is equally consistent with the
creator's own stated claim of "no pattern."

**Implementation.** `research/hypotheses/hash_chain.py`. (1)
Bit-frequency-by-position on the free bits (MSB-indexed), chi-square GOF
per position with Bonferroni correction; (2) serial autocorrelation
(Pearson + Spearman) between consecutive normalized keys with a
20,000-resample permutation test; (3) NIST-style runs test on the
concatenation of all 2,415 free bits across puzzles #2-70; (4) a
20,000-trial Monte Carlo null of synthetic uniform-in-range datasets;
(5) walk-forward comparison of four predictors (naive midpoint, running
mean, last value, OLS-on-`n`) for `N=5..69`.

**Parameters searched.** Bit position 0-39 (support ≥30 puzzles);
consecutive-pair lag-1 autocorrelation; runs test on 2,415 bits;
walk-forward window `N=5..69` with 4 competing predictors.

**Prediction.** No prediction is derivable for puzzle #71's key value
under this hypothesis class from ciphertext-only data — the only
rational test is whether the output bits show any detectable structural
deviation from uniform randomness (a necessary, not sufficient,
condition for ruling the class in or out).

**Test result.** Bit-frequency: 40 positions tested, 0/40 significant
after Bonferroni correction (max chi2=8.10 at position 29, uncorrected
p=0.0044, does not survive correction). Autocorrelation: Pearson
r=0.0580 (p=0.638), Spearman r=0.0543 (p=0.660). NIST runs test:
p=0.335. Monte Carlo (20,000 sims): all five summary statistics
p≥0.15. Walk-forward: naive midpoint baseline MSE=0.0736 is the
*lowest* of all four predictors (running mean 0.0772, last-value 0.1369,
OLS-on-n 0.0888) — nothing built from history beats guessing the
midpoint.

**Reason rejected/retained.** Every empirical randomness test came back
statistically indistinguishable from the Monte Carlo null (all p≥0.15,
none significant), and the walk-forward test confirms no exploitable
serial structure. Analytically, BIP32 non-hardened derivation is
provably indistinguishable from an ideal PRF given only child outputs
(no chaincode/parent_priv leak in this dataset) — distinguishing it from
true randomness would be a break of HMAC-SHA512 itself. This makes the
hypothesis class **unfalsifiable from the available ciphertext-only
data by construction**: passing these randomness tests neither confirms
this specific mechanism over plain uniform sampling nor rules it out.
**Verdict: unfalsifiable from data alone** (not "retained" — it
contributes zero exploitable reduction in the #71 search space; the
walk-forward midpoint baseline being best-of-4 is itself evidence
against any of the four candidate predictors, hash-based or not).

## 5. Cross-puzzle bit/byte persistence (`cross_puzzle_persistence`)

**Hypothesis.** Bits "persist" across puzzles: some bit position or
byte-level pattern in the free (post-leading-bit) portion of key `n`
correlates with the corresponding position in key `n+1, n+2`, etc.;
and/or the puzzle index `n` itself predicts the normalized key position
(trend or periodicity mod 8/16/32, suggesting byte/word-aligned
generation quirks).

**Historical evidence.** Not separately investigated in Archaeology (out
of scope for this statistical test); consistent with, but not itself
verifying, the creator's "no pattern" statement, and consistent with the
prior rejection of the sequential-counter hypothesis under the same
Monte Carlo methodology.

**Implementation.** `research/hypotheses/cross_puzzle_persistence.py`.
19 statistics: |Spearman| and |Pearson| of `n` vs normalized(`n`);
|autocorrelation| of the normalized sequence at lags 1-5; one-way ANOVA
F-stat of normalized grouped by `n mod {8,16,32}`; mean right-justified
Hamming-distance fraction between consecutive keys' free bits at lags
1-5; pooled and per-key Hamming-weight deviation from Binomial(k,0.5);
max/mean LSB-aligned bit-position correlation between consecutive keys'
free bits (offsets 0-19). 20,000-trial Monte Carlo null (interval-exact,
via `random.getrandbits`), with both Bonferroni and an exact family-wise
Monte Carlo correction (each null replicate's own best-of-19 p-value
forms the correction distribution). Walk-forward: linear regression of
normalized(`n+1`) on normalized(`n`) fit on `n<=split` for splits
{10,20,30,40,50,60,65}, MSE vs naive midpoint baseline.

**Parameters searched.** 19 statistics × 20,000 Monte Carlo replicates;
7 walk-forward train/test splits.

**Prediction.** A real persistence effect would produce a bit
position/byte alignment or lag correlation standing out from 20,000
random-null replicates even after accounting for testing 19 statistics
at once, and a lag-1 regression predictor that beats the midpoint
baseline out of sample.

**Test result.** Most extreme of 19: lag-3 autocorrelation of normalized
position = 0.3016 (null mean 0.0976 ± 0.0725), raw one-sided p=0.0115.
Second: ANOVA F (mod 32) = 1.718 (null mean 1.033), p=0.050. All other
17 statistics (including every direct bit-position-persistence and
Hamming-distance/weight test) land at p=0.09-0.99. Consecutive-key
Hamming distances/weights sit almost exactly at their binomial
expectations (deviations 0.0002-0.013). Walk-forward: lag-1 persistence
predictor beat the naive midpoint baseline in only 2 of 7 splits, with a
sign-unstable fitted slope (-0.31 at split `N=10` vs +0.21 at `N=40`).

**Monte Carlo p-values.** Bonferroni threshold for 19 tests: 0.002632.
The single most extreme raw result (p=0.0115) does not survive
(0.0115 > 0.002632). Exact family-wise Monte Carlo correction (built
from 20,000 null replicates' own best-of-19 statistic, mean 0.0568,
median 0.0406, 5th pct 0.0030): the real data's best result lands at the
**17.965th percentile** of that null — pure random data produces an
equally strong "best of 19" excursion roughly 1 time in 6.

**Reason rejected.** No statistic survives multiple-comparison
correction by either method, and the one nominally low raw p-value is
fully explained by the multiple-comparisons load of testing 19
correlated statistics (confirmed directly, not just asserted, via the
exact family-wise Monte Carlo null). The walk-forward predictor
underperforms the naive baseline more often than not, with an
unstable sign, ruling out even a weak exploitable trend. **Verdict:
rejected.**

## 6. Timestamp / block-hash seeding at creation (`timestamp_creation`)

**Hypothesis.** The generator's per-puzzle free bits were seeded or
otherwise influenced by real-world timing around the January 2015
creation/funding period — e.g. a Unix timestamp used as an RNG seed, a
Bitcoin block hash/height near the funding transaction, or clock-jitter
from generating 256 keys in a tight loop — such that `lower_bits(n)` is
recoverable (exactly or via simple modular/XOR/substring transform) from
a nearby real-world timestamp or block value.

**Historical evidence.** Used the project's on-chain forensics plus a
fresh, independent re-fetch against blockstream.info (2026-08-19) to pin
down the exact real-world funding event: all 71 puzzle addresses (#1-71)
were funded in ONE transaction
(`08389f34c98c606322740c0be6a7125d9860bb8d5cb182c02f98461e5fa6cd15`),
block height 339085, block time 1421345234 (2015-01-15T18:07:14 UTC),
block hash
`0000000000000000188de542fd76b1676c4be6c380b39ddea119358c290cebd7` —
confirmed live via the blockstream.info block-height and block-hash
endpoints. Also fetched 21 additional real blocks around this event
(fine window ±5 heights, plus daily-spaced heights ±5 days) to allow for
generation happening somewhat before the payout. This is the strongest
piece of independently-verifiable (not creator-claim-dependent) evidence
in the entire research program: anyone can re-fetch this txid and
confirm it.

**Implementation.** `research/hypotheses/timestamp_creation.py`
(deterministic, seed 20260819, ~123s runtime). Three families, each with
its own matched Monte Carlo null (structure-aware: each null puzzle
draws free bits uniformly from `[0, 2^(n-1))`, avoiding the LCG
hypothesis's earlier precision-confound pitfall from the start): (1)
fixed-value test (no search) against block time/mediantime/height/hash
mod `2^(n-1)`; (2) nearby-blocks search over 21 real blocks × 3 value
types, plus hex-substring match; (3) full brute-force scan of all
5,097,600 Unix timestamps in Jan 1 – Mar 1 2015, testing `T mod 2^(n-1)`
and `(T+n) mod 2^(n-1)` for `n=2..63`; (3b) walk-forward: best `(T,
relation)` selected using only training puzzles `n=2..50`, evaluated
with no further fitting on held-out `n=51..70`.

**Parameters searched.** Test 1: 4 fixed values × 2 statistics = 8
comparisons. Test 2: 21 blocks × 3 value types = 63 combos, plus 54
puzzles × 42 hash-strings = 2,268 substring checks. Test 3: 5,097,600
candidate timestamps × 2 relation forms × 62 puzzles ≈ 632M comparisons
per scan, repeated across 100 Monte Carlo control trials + 1 real pass
(≈63.9 billion total comparisons). Test 3b: identical search restricted
to 49 training puzzles.

**Prediction.** If true: the real funding block's timestamp/hash/height
would show anomalous bit-agreement with `lower_bits(n)` far beyond the
null; or some timestamp within the 5.1M-candidate window would explain
far more than the ~3-4 puzzles random chance explains across such a
large search; or a `(T, relation)` pair fit only on `n<=50` would predict
held-out `n=51..70` bit-agreement above the 0.5 chance baseline.

**Test result.** Test 1: smallest raw p=0.1994 (block height,
bit-agreement fraction), Bonferroni-corrected (×8) to 1.0000; exact-match
counts (0,1,1,2) matched the null's ~1-per-value expectation. Test 2:
best bit-agreement p=0.3209, best exact-match p=0.9998, hex-substring
p=1.0000 (real data had **zero** substring hits vs null mean 0.068).
Test 3: the single best-fitting timestamp anywhere in the entire
two-month window explained only 3 of 62 puzzles — *below* the null's own
average of 3.44-3.69 matches, p=0.9901/1.0000/1.0000. Test 3b: 0/20
exact held-out hits (chance-expected), and mean held-out bit-agreement =
**0.4861, below the 0.5000 chance baseline** — the fitted predictor
performs worse than guessing out of sample, the clearest possible
walk-forward failure.

**Monte Carlo p-values.** Smallest across all families: 0.1994
(pre-correction; 1.0000 after Bonferroni ×8). Search-based families
(nulls already absorb the multiple-comparisons problem by re-running the
identical search on random controls): p ∈ [0.32, 1.00], with Test 3's
real result landing *below* the null's own mean.

**Reason rejected.** Across three independent, search-matched Monte
Carlo tests — including an exhaustive brute-force scan of all 5.1
million candidate timestamps in the full creation window under two
relation forms — no statistic came close to the significance a real
timing-based generator relationship would produce, and the walk-forward
check performed *worse* than the trivial chance baseline out of sample.
This does not rule out timestamp influence via an untested transform
(arbitrary hash functions/encodings are an unbounded search space), but
finds nothing under the direct, substring, and simple-modular
relationships tested, searched completely within the specified window.
**Verdict: rejected.**

## 7. Seed/passphrase-guessing attack (Electrum Type-1 and classic SHA256(master+n))

**Hypothesis.** Hypothesis 4 (`hash_chain`) established that a real
seed-derived hash chain or HD derivation is *statistically unfalsifiable
from output bits alone* — it is indistinguishable from random by design.
This is the complementary attack: rather than looking for statistical
structure, directly guess the seed/passphrase for two historically-plausible
deterministic-wallet schemes and check whether the derived, masked key
matches any real solved puzzle. Scheme A: Electrum "Type-1" (pre-2.0)
wallet — 100,000-round SHA-256 key stretching of a 16-byte seed produces a
master secret exponent; child key `n` is `(secexp + SHA256d(f"{n}:{for_change}:"
+ master_pubkey)) mod secp256k1_order`. Scheme B: classic "Type-1"
brainwallet-style `child_key(n) = SHA256(masterstring formatted with n)` in
several plausible formats.

**Historical evidence.** Scheme A reproduced exactly from the current
`spesmilo/electrum` source (`electrum/keystore.py Old_KeyStore`,
`electrum/old_mnemonic.py`, fetched 2026-08-19) and validated against a real
published Electrum test vector before use (`tests/test_seed_attack.py`).
Scheme B is the classic Type-1 deterministic-wallet formula documented by
Mike Caldwell (2011) on the Bitcoin wiki, flagged as unfinished business in
Archaeology and in hypothesis 4's own writeup above. Both raw derivations get
the puzzle creator's own stated masking applied (keep low `n-1` bits, force
bit `n-1` high) before comparison against `data/solved_puzzles.json`.

**Implementation.** `src/seed_attack.py` (the validated module; unmodified,
reused unchanged across every category below) plus five category-specific
candidate-construction and test-harness scripts in
`research/hypotheses/seed_guessing/`: `puzzle_culture` (bitcoin-puzzle- and
creator-specific phrases), `common_passwords` (SecLists `10k-most-common.txt`),
`brainwallet_cracked` (real, individually documented cracked brainwallet
passphrases from published research), `crypto_culture_quotes` (genesis
coinbase text, whitepaper, cypherpunk/crypto-anarchist lines, Satoshi's
documented quotes, community slogans), and `trivial_and_sequential`
(degenerate/sequential hex patterns, small integers, common words). Each
category ran candidate phrases through classic Type-1 across all 8 formats
in `FORMATS`, and through Scheme A via three cheap 16-byte hex-seed bridges
(`SHA256(phrase)[:16]` hex, `MD5(phrase)` hex, raw UTF-8 bytes
zero-padded/truncated to 16 bytes) each run through the real, unshortcut
100,000-round stretch — not an approximation. `tests/test_seed_attack.py`'s
three controls (real Electrum known-answer vector, Electrum positive
control, classic Type-1 positive control) were re-confirmed passing before
and after this work.

**Parameters searched.** 164,424 classic Type-1 candidates (masterstring x
format combinations) and 10,939 Electrum Type-1 candidates (hex-seed x
derivation-bridge combinations, each given the real 100,000-round stretch)
across the five categories — 175,363 total candidate-derivation attempts.
See `research/hypotheses/seed_guessing/SUMMARY.md` for the full per-category
breakdown, candidate lists, and cited sources (SecLists; Castellucci, DEF
CON 23 2015; Vasek/Bonneau/Castellucci/Keith/Moore, Financial Cryptography
2016; project archaeology and on-chain forensics files).

**Prediction.** If any tested phrase is the real seed, the masked derived
key would exactly equal the real key for at least one puzzle at a
statistically meaningful size (`n >= 20`, chance rate under `2^-19`) —
and, per the task's own framing, a match across two or more puzzles
simultaneously would be overwhelming confirmation.

**Test result.** Zero matches at any statistically meaningful puzzle size,
in any category, under either scheme.
`test_candidate_against_dataset` returned non-empty results only for the
mathematically expected chance noise at small `n` (puzzle `n<=1` is
structurally degenerate — `apply_puzzle_mask` forces `masked=1`
unconditionally — and `n=2..~15` carry too few free bits to be
informative); every such coincidence was checked against a pre-registered
Bonferroni-style significance filter
(`expected_spurious_count = candidates * product(2^-(n_i-1)) < 0.001`) and
