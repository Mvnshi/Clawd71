# Bit-Frequency-by-Position and Runs-Test Analysis

Puzzle #71 research -- statistical test of the null hypothesis that the
"free bits" (private key minus the forced leading bit 2^(n-1)) of solved
puzzles #1-70 are independent, uniform (fair-coin) bits, as claimed by the
puzzle creator ("just consecutive keys from a deterministic wallet").

Generated by `bit_frequency_runs.py`. RNG seed = 20260819. Monte Carlo simulations = 20,000.

## 1. Data / method

- 70 puzzles (n=1..70) loaded from `data/solved_puzzles.json`.
- Free-bit string per puzzle = `lower_bits_hex` as an (n-1)-bit, MSB-first, zero-padded binary string (n=1 contributes 0 bits).
- Cross-checked against the dataset's own `binary` field (`binary[1:]`) for all 70 puzzles: exact match.
- Concatenated free-bit sequence length: **2415 bits** (= sum_{n=1}^{70} (n-1) = 69*70/2).
- Per-position tests restricted to positions reaching **n_valid >= 10** puzzles (expected cell count >= 5), i.e. positions 0..59 (60 positions tested; positions 60..68 skipped, too few puzzles reach that depth).
- Null model for Monte Carlo: for each puzzle n, draw lower_bits ~ Uniform{0..2^(n-1)-1} independently -- i.e. the *true* per-puzzle interval width, not a naive fixed-length or unconstrained draw.

## 2. Per-bit-position chi-square (vs 50/50)

Only positions with >= 10 puzzles reaching that depth are shown/tested (sample size shrinks for deeper positions since early, small puzzles have few or zero free bits).

- Most significant single position (raw/uncorrected asymptotic chi2 p-value): position **29** (chi2=8.1000, n_valid=40, n_ones=29), raw p = 0.0044.
- Same position, Bonferroni-corrected across 60 tested positions: p = 0.2656.
- Same family, Benjamini-Hochberg FDR-adjusted minimum: q = 0.2151.
- Monte Carlo-calibrated p-value for that same position's chi2 statistic (fraction of 20,000 true-interval-constrained null simulations producing an equal-or-larger chi2 at that position): p_MC = 0.0061.
- **Omnibus test** -- max chi2 across all 60 tested positions (this is the statistic that correctly accounts for "testing many positions and taking the best one"): observed max chi2 = 8.1000 at position 29; Monte Carlo p-value (fraction of 20,000 null simulations whose own max-over-positions chi2 is >= observed) = **p_MC = 0.2033**.

## 3. Overall frequency test (all 2415 free bits pooled)

- Total ones = 1193 / 2415 (0.4940); expected under H0 = 1207.5 (0.5000).
- chi2 (1 dof) = 0.3482, asymptotic p = 0.5551.
- Monte Carlo p-value (20,000 true-interval-constrained null sims) = **0.5704**.

## 4. Runs test (NIST SP 800-22 style, on the full 2415-bit concatenated sequence)

- Proportion of ones (pi) = 0.4940.
- Pre-test |pi - 0.5| >= 2/sqrt(n) check: passes (test applicable).
- Observed number of runs V_obs = 1231 (expected under H0 ~ 1208.5).
- NIST asymptotic p-value (erfc formula) = 0.3352.
- Monte Carlo p-value for runs count vs the true-interval-constrained null (20,000 sims, two-sided extremity around the null median) = **0.3595**.
  - Null runs-count distribution: mean=1208.12, sd=24.64, median=1208.0, observed=1231.

## 5. Longest-run statistics (simplified: single longest run in the full concatenated sequence, not the NIST block-partitioned variant)

- Longest run of 1s observed = 10 bits. Null distribution: mean=10.58, sd=1.86, 95th pct=14.0. Monte Carlo p (>= observed) = **0.6965**.
- Longest run of 0s observed = 9 bits. Null distribution: mean=10.55, sd=1.85, 95th pct=14.0. Monte Carlo p (>= observed) = **0.9049**.

**Overall verdict: NOT SIGNIFICANT after multiple-comparison correction (alpha=0.05).**

## 7. Interpretation

No statistic -- individual bit positions (Bonferroni- or BH-corrected), the omnibus max-chi-square-over-positions test, overall bit frequency, the runs test, or longest-run-of-ones/zeros -- survives multiple-comparison correction at alpha=0.05 against a null model that correctly respects each puzzle's true interval width. This is consistent with the puzzle creator's claim that the keys are unpatterned (masked 'random-looking' deterministic-wallet output) and gives no statistical basis for narrowing the search interval for puzzle #71 below the full [2^70, 2^71) range implied by the puzzle index alone.

Per the task's anti-bullshit rule: this result (no significant deviation from a fair-coin, uniform-in-interval null) is reported as-is. A null result is the expected and statistically honest outcome here, not a failure of the analysis.
