## Anti-bullshit rule applied

Nothing below is reported as a finding merely because it fits the 70 known keys.
Every statistic is checked against an explicit Monte Carlo null model: for each
puzzle n, draw key_int ~ Uniform{2^(n-1), ..., 2^n - 1} independently -- i.e. the
puzzle creator's own stated null ("no pattern, just deterministic-wallet keys
masked to set difficulty") made concrete and falsifiable. Where many combinations
were tried (which modulus, which polynomial degree, which recurrence order/start
position), a **family-wise** Monte Carlo p-value is reported: the identical search
procedure is re-run on every simulated null dataset, so the p-value already accounts
for how many chances-to-look-good were taken.

## Part C: exact modular linear recurrence search

For order p in {1,2,3} and modulus M in {secp256k1 group order N, 2^32, 2^64}, every
valid window start s is tried: fit key_int(t) = c_1*key_int(t-1) + ... +
c_p*key_int(t-p) + c_0 (mod M) exactly (Gauss-Jordan elimination mod M) from the
minimal window of 2p+1 consecutive points, then count how many *additional* held-out
points immediately following the window the fitted recurrence continues to predict
correctly (run length) before the first miss. The reported statistic per modulus is
the best (longest) run length found across every (p, s) combination tried -- and the
**identical exhaustive search** is repeated on every simulated null dataset, so the
multiple-comparisons load of trying ~198 combinations per modulus is already absorbed
into the Monte Carlo null distribution of "best run length found by an exhaustive
search of this size, by pure chance."

N=3000 null datasets per modulus (search took 3000 x ~198 combos x 3 moduli).

| Modulus | Best real run length (points predicted beyond fit window) | (order p, start s) achieving it | Null mean best-run | Null max best-run | MC p (null best-run >= real) |
|---|---|---|---|---|---|
| secp256k1 order N | 0 | n/a (no window ever extended) | 0.0627 | 2 | 1.0000 |
| 2^32 | 0 | n/a (no window ever extended) | 0.0357 | 2 | 1.0000 |
| 2^64 | 0 | n/a (no window ever extended) | 0.0380 | 2 | 1.0000 |

Interpretation note: because a spurious extension requires the fitted recurrence to
match a *held-out* value modulo a large modulus (2^32, 2^64, or the ~2^256 curve order)
by pure chance, the per-step coincidence probability is astronomically small for large
n (~1/M); it is only non-negligible for the earliest, smallest-valued puzzles, where it
is correctly captured by the null model since the null also draws from the true (small)
interval at those n. A real best-run-length of 0 across the board (or matching the null)
means the search never found even a single non-trivial exact recurrence extension --
expected under "no pattern," and not evidence of anything.

## Interpretation

- **Part A (polynomial fits):** none of the degree-1/2/3 least-squares fits to
  normalized(n) are tighter than a same-degree fit to random per-puzzle-interval null
  data would typically achieve (family-wise MC p = 0.1930). normalized(n) does not
  follow a low-degree polynomial trend in n.
- **Part B/D2 (modular residues):** none of key_int(n) mod {2,3,5,7,16,256} or the
  first-difference sequence mod {2,4,8} show non-uniform residues beyond chance
  (combined 9-test family-wise MC p = 0.8556).
- **Part C (linear recurrence):** the exhaustive search over 3 recurrence orders,
  ~66-68 window starts each, and 3 moduli (secp256k1 order, 2^32, 2^64) found no
  exact recurrence that predicts held-out puzzle keys better than the same search
  applied to random per-puzzle-interval null data. Concretely: the best (longest)
  held-out run length found anywhere in the search, on the real data, across all
  three moduli, was 0 points -- i.e. no small-order recurrence fit even
  1 consecutive point beyond its minimal fit window, let alone the >3-points-beyond-
  coincidence bar posed in the task brief.
- **Part D1 (lag-1 autocorrelation):** normalized(n) shows no significant lag-1
  autocorrelation (MC two-sided p = 0.6280).

**Overall: no statistically significant modular, polynomial, differencing,
or small-order-linear-recurrence pattern was found in key_int(n) or normalized(n)
across puzzles #1-70, after Monte Carlo calibration and multiple-comparison
correction.** This is consistent with the puzzle creator's stated generation process
("no pattern, consecutive keys from a deterministic wallet, masked with a leading
000...0001 to set difficulty") and is reported here as a valid, expected negative
result per the project's anti-bullshit rule -- not a failure of the analysis.
