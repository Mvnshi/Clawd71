# Bitcoin Puzzle Transaction — Archaeology of Creator Statements & Community Analyses

Research date: 2026-08-19. Compiled via WebSearch/WebFetch against BitcoinTalk, GitHub,
on-chain explorers, and secondary press. All web-search summaries below were
independently corroborated where a direct WebFetch succeeded; single-source
claims are flagged as such.

## 1. On-chain ground truth (independently verifiable, not reliant on any human claim)

- **Funding transaction:** `08389f34c98c606322740c0be6a7125d9860bb8d5cb182c02f98461e5fa6cd15`
- **Block:** 339085
- **Timestamp:** 2015-01-15 18:07:14 UTC
- **Outputs:** 256 addresses, values 0.001 BTC (puzzle #1) up to 0.256 BTC (puzzle #256), total 32.899 BTC
- Verified directly via mempool.space block explorer (2026-08-19).
- Puzzle #71's address 1PWo3JeB9jrGwfHDNpdGK54CRas7fsVzXU is one of these 256 original outputs (later re-funded at 10x in 2017 and again in 2023 — see §3).

This is the only fact in this document that does not depend on trusting an anonymous forum poster.

## 2. Earliest public discussion found (NOT the creator)

**Thread:** "Bitcoin puzzle transaction ~32 BTC prize to who solves it"
**URL:** https://bitcointalk.org/index.php?topic=1306983.0
**OP author:** `Bulista`
**OP date:** December 28, 2015, 04:12:47 PM — i.e. **~11.5 months after the funding tx**, not Jan–Mar 2015.
**Quote (paraphrase confirmed via WebFetch of the live thread):** "those 32.896 BTC were sent to multiple addresses, all the private keys of those addresses seem to be generated by some kind of formula," followed by a list of the first several solved key values (3, 7, 8, 21, 49, 76, 224, 467, 514, 1155, 2683, 5216, 10544, ...).

Important: Bulista is the *discoverer/discussant* who popularized the puzzle and built early cracking tools, not the creator. Multiple secondary sources (Decrypt, GitHub aggregators) explicitly confirm Bulista is "not the creator," just the person who found and publicized an already-14-month-old transaction.

**Search result for a January 2015 primary source (Reddit r/Bitcoin or earlier BitcoinTalk) came up empty.** I ran multiple targeted searches (site:reddit.com, transaction-hash search, block-height search) and found no Jan–Mar 2015 primary discussion thread. One search-engine summary asserted a BitcoinTalk user "amaclin" first posted about the tx in January 2015, but on independent verification `amaclin` is a real BitcoinTalk user (profile u=197593) known instead for the October 2015 transaction-malleability attack — an unrelated topic. I could not corroborate any amaclin post about the puzzle transaction, and consider that specific claim an unverified/likely-erroneous search-summarization artifact. **Conclusion: the puzzle appears to have gone essentially unnoticed publicly for roughly a year after creation** — the "widely quoted" origin story only enters the public record via the Bulista thread in Dec 2015 and the creator's own post in Apr 2017 (below).

## 3. The creator's own statement — primary source located

**Account:** `saatoshi_rising`
**BitcoinTalk profile:** https://bitcointalk.org/index.php?action=profile;u=991321
**Registration date:** April 27, 2017, 05:43:11 AM
**Total lifetime post count: 1** (per profile page, confirmed by WebFetch 2026-08-19) — i.e. this account exists to make exactly one post.
**That post:** in the same thread as above, topic 1306983, dated **April 27, 2017, 06:41:08 AM** — 56 minutes after the account was created.

**Content (post excerpt, confirmed via WebFetch of the profile's "show posts" listing):** The poster identifies themself as the puzzle's creator, responds to community criticism that funding the very-high-difficulty range (#161–256) was wasteful, and says:

> "There is no pattern. It is just consecutive keys from a deterministic wallet (masked with leading 000...0001 to set difficulty). It is simply a crude measuring instrument, of the cracking strength of the community."

This exact quote (word-for-word) is reproduced identically across a large number of independent secondary sources — a GitHub README (HomelessPhD/BTC32), a Medium post, an X/Twitter screenshot (https://x.com/James554291102/status/1868279018501603397, attributing it explicitly to "saatoshi_rising on Bitcointalk"), roadhero/Bitcoin-Puzzle-Info's README, and several aggregator/directory sites (privatekeys.pw, privatekeyfinder.io). The consistency of wording across sources that don't cite each other is good evidence the quote is being copied from a real forum post rather than invented independently by any one of them.

The same post also states the poster will move BTC from the #161–256 range down into the unsolved lower range, calling the original #161-256 allocation inefficient/"silly," and praises tools built by the community (specifically namechecking the "Large Bitcoin Collider").

**Corroborating on-chain action:** On 2017-07-11, funds were in fact moved from puzzle addresses #161–256 down into addresses #53–160, roughly 10x'ing those rewards — exactly matching what this post said would happen. A further ~872 BTC top-up occurred 2023-03-16, again matching later behavior attributed to the same "creator" persona. This is circumstantial but meaningful corroboration: whoever posted this held (or coordinated with whoever held) the private keys controlling the puzzle-funding wallet, since only that party could execute the follow-up on-chain moves.

**What this is NOT:** a cryptographically signed message from the address that funded the original 2015 transaction. No such signature has been located. The "creator" identity is therefore **plausible and behaviorally corroborated, but not cryptographically proven** — exactly the "widely-quoted but independently unverified" status assumed in the task brief. Treat the "no pattern... deterministic wallet" statement as the creator's own claim about their process, not as a verified fact about the actual key-generation algorithm.

**Tangential finding — active scam site:** `saatoshirising.wiki` currently presents itself as "the puzzle creator" and solicits a "$5000 contribution via QR code" in exchange for supposedly revealing puzzle #71's private key. This is unrelated to the 2017 BitcoinTalk account (different medium, transparently a payment-collection scam) and should not be treated as a source of any kind — flagging it here only so it isn't mistaken for a legitimate lead if it resurfaces in later searches.

## 4. Community statistical analyses found

### 4a. HomelessPhD/BTC32 — "alpha" normalized-position analysis
**URL:** https://github.com/HomelessPhD/BTC32 (README + `BTC32_Analysis/` folder)
**Method:** Computes `alpha = (key − 2^(n−1)) / 2^(n−1)` per solved puzzle — i.e. exactly the same normalized-position statistic already present as `normalized` in our own `solved_puzzles.json`. Contains MATLAB/Octave scripts (`BTC32_dummy_analysis.m`, `BTC32_dummy_simulation.m`), a raw `alpha.csv`, histograms (`hist_1_63.png`, `hist_all.png`, `hist_upper_5th.png`), and autocorrelation plots.
**Claimed finding:** "The Private Keys are more probable to be found at {0.3–0.5} and {0.6–0.8}," with a small extra cluster noted around {0.82–0.83}.
**Their own caveat:** Autocorrelation analysis "appeared as noise" (no linear tendency/relation), and the author explicitly lists competing explanations — non-random clustering vs. small-sample statistical noise vs. plain uniform randomness — without picking one.
**Relevance / action item for our own work:** This is exactly the kind of claim the task's anti-bullshit rule is built to catch — a histogram bump on ~66 samples with no null-model comparison offered. We should reproduce this "0.3–0.5 / 0.6–0.8 more probable" claim against our own Monte Carlo null (uniform-random controls of matching sample size) using our verified 70-puzzle dataset, since it is now a concrete, falsifiable prior claim from the community rather than one we invented. Given 66-70 samples of independent U(0,1) draws, an emergent-looking bimodal-ish histogram bump is exactly what you'd expect by chance a large fraction of the time — this should be checked quantitatively, not dismissed or accepted by eye.

### 4b. mlartab/bitcoin-puzzle-systematic-analysis — targeted #71 attempt, negative result
**URL:** https://github.com/mlartab/bitcoin-puzzle-systematic-analysis
**Stated purpose:** Explicitly aimed at recovering puzzle #71's key by reverse-engineering the wallet/seed from the 69 (at time of writing) already-solved puzzles.
**Methods tried:** BIP32 HD-wallet passphrase brute force against wordlists; brainwallet-style SHA256(passphrase) derivation with various separators; full exhaustive search of the 32-bit seed space for Python's `random`, C's `rand()`, and Java's `Random`; Z3 SAT-solver attempt to recover MT19937 (Mersenne Twister) internal state from output bits; keyhunt/GLV-endomorphism brute force (~12M keys/sec on an i5).
**Result:** No key found. Explicitly rules out: standard-library PRNGs as the generator ("The puzzle wasn't made with Python's `random`," "likely doesn't use MT19937 at all"), and notes that BIP32's 256-bit chain code cannot be recovered from public keys alone even given leaked child keys — so a naive "just derive from a known seed" attack against an HD wallet is cryptographically sound against this puzzle regardless of how "consecutive" the keys are.
**Relevance:** A serious prior negative result specifically on #71. We should not re-run exhausted PRNG-seed searches without first checking whether our own approach differs meaningfully from what's documented here (it save compute to know a 32-bit PRNG-seed brute force was already fully exhausted with no hit).

### 4c. rya.nc forensic write-up (contemporaneous with the 2015 creation)
**URL:** https://rya.nc/forensic-bitcoin-cracking.html
**Content:** Independent forensic account, written shortly after discovery, noting that puzzle outputs #1–20 were spent almost instantly on 2015-01-15 itself ("suggesting a bot was monitoring the network"), with the author's own `brainflayer` tool clocking ~1.5M guesses/sec against competing solvers estimated around 27–28M guesses/sec (outputs #46, #50). The author states plainly they don't know who made the transaction and would "love to hear from whoever made it" — i.e. as of this writing the creator had not yet come forward (consistent with the 2017 reveal being the first such claim).
**Relevance:** Useful as an early, non-creator-affiliated technical account of the puzzle's mechanics and confirms the "masked leading zeros, then random-looking remainder bits" structure was already publicly obvious from the raw key values well before the creator's 2017 statement — i.e. the "how it's masked" part of the creator's claim is independently visible on-chain and doesn't rest on trusting the creator at all. Only the "consecutive" / "deterministic wallet" / "no pattern" parts are unverifiable claims about the *generation process* rather than the *masking* structure.

### 4d. Not found
No community analysis was located that claims to have found a *validated* (null-model-tested, walk-forward-tested) exploitable pattern. Every serious analysis I could access (4a, 4b) either explicitly reports a negative/inconclusive result or reports a raw-eye-catching statistic (4a) without a randomness-null comparison — which is precisely the gap our own Monte Carlo methodology is designed to close.

## 6. Implication for the anti-bullshit workflow

Nothing above should be treated as evidence that the puzzle keys contain exploitable structure. The creator's own claim, if taken at face value, is a claim of *no* structure beyond "consecutive keys from a deterministic (HD) wallet" — and BIP32/BIP44-style HD wallets are specifically designed so that even fully sequential child-key indices produce cryptographically independent-looking private keys (the chain code is the load-bearing secret, and it cannot be inferred from any number of exposed child keys or public keys). The one existing community study that targeted #71 directly (4b) already exhausted the most obvious weak-generator hypotheses (small-seed PRNGs, brainwallet passphrases) with no hit. Any reduction in our own candidate search space for #71 needs its own Monte-Carlo-validated statistical case — the "0.3–0.5 / 0.6–0.8 more probable" claim from 4a is the single most concrete pre-existing claim worth formally re-testing against a random null before it's used for anything.
